---
title: "Badges"
description: "How to state a conformance claim."
---

A claim names the classes, the time models, the draft revision, and how it was established (AWP-CNF-003, AWP-CNF-005, AWP-VER-009). The [suite](/conformance/test-suite) prints the wording its report supports:

| Report | Claim |
|---|---|
| No failure, nothing untested in scope, manual evidence attached | `Core World (streaming): AWP-conformant against 0.1-draft.7 (awp-conformance 0.1.0a1)` |
| No failure, something untested | `Core World (streaming), self-assessed against 0.1-draft.7` |
| A failure | No claim |

Profiles join the class with `+`, and experimental profiles say so: `Core World + sim (lockstep), self-assessed against 0.1-draft.7`; `Core World + robotics (experimental; no force monitoring)` (AWP-CNF-006, AWP-ROB-003).

A badge carries the same words:

```markdown
![AWP: Core World, self-assessed against 0.1-draft.7](https://img.shields.io/badge/AWP-Core_World%2C_self--assessed_0.1--draft.7-555)
```

Publish the suite's `report.json` next to the badge so the claim can be checked.
