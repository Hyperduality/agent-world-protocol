No world SDK is published yet. The starting point is [awp-sim](/adapters/awp-sim), the reference world, whose engine is written to be read: a sans-IO state machine that takes messages and the current time and returns what to send.

<Steps>
  <Step title="Run the reference world">
    ```bash
    pip install "awp-python @ git+https://github.com/Hyperduality/awp-python"
    awp-sim serve                    # or: awp-sim serve --mode lockstep
    awp-sim demo                     # in another terminal
    ```
  </Step>
  <Step title="Write your manifest">
    `awp-sim manifest` prints a complete, valid [world manifest](/spec/session/world-manifest). Replace its embodiments, observation channels, and action schemas with your world's; validate the result against [`world-manifest.schema.json`](/api-reference/schemas/world-manifest).
  </Step>
  <Step title="Implement the loop">
    The engine is [`src/awp_sim/world.py`](https://github.com/Hyperduality/awp-python/blob/main/src/awp_sim/world.py). Each requirement it implements is cited by ID at the point where it applies, so it reads alongside the [specification](/spec/index): admission checks, the action lifecycle, lockstep advances, the watchdog, replay, and closing. Replace the simulated arm with your simulator or controller.
  </Step>
  <Step title="Check it">
    Record your world's traffic in the [trace format](/spec/wire-traces) and run the specification's trace checker over it, as awp-python does for every scenario (`scripts/check_traces.py`).
  </Step>
</Steps>

For a simulator, continue with [Wrap a simulator](/guides/wrap-a-simulator); for hardware, [Wrap a robot](/guides/wrap-a-robot).
