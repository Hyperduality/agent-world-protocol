---
title: "Observations"
description: "Typed, timestamped, multi-channel percepts — pulled per tick or pushed as streams."
icon: "eye"
---

Worlds expose named **observation channels**, each declaring a modality, encoding, schema, resolution, and nominal rate in the manifest. An agent subscribes to the subset it can consume.

<Tabs>
  <Tab title="Image">
  ```json
  { "channel": "rgb_main", "seq": 4211, "ts_mono_ns": 913004112000,
    "modality": "image/jpeg", "width": 1280, "height": 720, "payload": "<binary>" }
  ```
  </Tab>
  <Tab title="Proprioception">
  ```json
  { "channel": "proprio", "seq": 88123, "ts_mono_ns": 913004498000,
    "modality": "proprio/json",
    "data": { "joints_rad": [0.12, -1.04, 0.88], "gripper": 0.5 } }
  ```
  </Tab>
  <Tab title="Semantic event">
  ```json
  { "channel": "events", "seq": 74, "ts_mono_ns": 913004501000,
    "modality": "text/event+json",
    "data": { "event": "entity_appeared", "entity": "box_12", "frame": "world" } }
  ```
  </Tab>
</Tabs>

Delivery depends on the [time model](/concepts/time-models): in **lockstep**, frames are pulled per tick over the control plane; in **streaming**, they are pushed over the data plane with timestamps and sequence numbers, and the agent must tolerate staleness. Every frame carries enough metadata (`seq`, `ts_mono_ns`, channel binding) for the agent to reason about ordering and latency — see [timestamps and clocks](/spec/semantics/timestamps-and-clocks).
