---
title: "Security"
description: "TLS, authentication, session tokens, and the threat model."
---

- Production deployments MUST use TLS (`wss://`, gRPC over TLS). Plaintext is permitted only on loopback. `[AWP-SEC-001]`
- Worlds MUST authenticate agents before `initialize` completes; defined schemes: bearer token (`Authorization: Bearer`), mutual TLS. `[AWP-SEC-002]`
- `session.ready` returns an unguessable **session token** used for `session.resume` and for binding data-plane connections to the session. Tokens MUST be scoped to one session. `[AWP-SEC-003]`
- Data-plane endpoints MUST reject connections that do not present a valid session token. `[AWP-SEC-004]`

**Threat model (informative).** AWP assumes a potentially adversarial agent and a trusted world: all safety enforcement is world-side. A compromised world can feed false observations; agents operating in high-stakes settings SHOULD verify world identity (TLS pinning) and MAY cross-check observations against independent sensors.
