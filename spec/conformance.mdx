## Conformance classes

- **Core World** — implements every MUST in the Core profile on the world side. `[AWP-CNF-001]`
- **Core Agent** — implements every MUST in the Core profile on the agent side. `[AWP-CNF-002]`
- **Profile conformance** — a Core-conformant implementation additionally satisfying all MUSTs of a named [profile](/spec/profiles/core). Claims are per-profile and name the draft revision (e.g. "Core World + sim + robotics (experimental; no force monitoring), self-assessed against 0.1-draft.9"). `[AWP-CNF-003]`

## Requirement mapping

Every requirement ID has a row in the [requirement matrix](/spec/requirements) giving its side (world / agent / both), applicability (all / lockstep / streaming), feature gate (profile or capability key), and the assertion that tests it — or `manual` / `untestable` with the reason — with a separate entry for the agent side of a row where that side is tested differently. Each MUST/MUST NOT maps to at least one assertion, named after its requirement ID; SHOULD items generate warnings, not failures. The [conformance suite](/conformance/test-suite), `awp-conformance`, runs the assertions; each suite release targets one draft revision and reports a verdict per requirement ID. `[AWP-CNF-004]`

## Claiming conformance

An implementation MAY claim "AWP-conformant" for a class only if a suite release targeting the named draft revision reports, for every requirement in scope for that class, no failure and no requirement left untested, with the evidence for every `manual` row attached to the report. Any other claim MUST be labelled "self-assessed against 0.1-draft.N", naming the draft revision (AWP-VER-009), including a claim whose suite report passes every assertion it ran but leaves requirements untested. "AWP-compatible" carries no normative meaning. `[AWP-CNF-005]` See [badges](/conformance/badges).

## Experimental profiles

Profiles whose requirements depend on physical measurement — robotics in v0.1 — are **experimental**: no validated hardware harness exists, so their conformance cannot yet be established by the suite. Claims for experimental profiles MUST carry the word "experimental" and attach the evidence required by AWP-ROB-004. A profile leaves experimental status by RFD once a harness has validated at least two independent implementations. `[AWP-CNF-006]`
