---
title: "Preemption"
description: "What a new action does to a running one — per-type policy."
---

Each action type declares its preemption policy in the manifest; the submitter selects one of the declared options per submission. `[AWP-PRE-001]`

| Policy | Semantics |
|---|---|
| `queue` | New action waits; executes after current terminal state. Queue depth bounded by `max_queue` (manifest); overflow → `AWP_QUEUE_FULL`. `[AWP-PRE-002]` |
| `replace` | Current action → `preempted` (after safe transition), new action starts. `[AWP-PRE-003]` |
| `blend` | World merges trajectories (continuous control); both actions report status, the replaced one ends `preempted` with `blended: true`. `[AWP-PRE-004]` |
| `reject` | New submission is rejected with `AWP_BUSY` while one is running. `[AWP-PRE-005]` |

**Concurrency groups.** The manifest MAY partition action types into `concurrency_groups`; preemption applies within a group, and actions in different groups run concurrently (e.g. `base_motion` vs `gripper`). `[AWP-PRE-006]`
